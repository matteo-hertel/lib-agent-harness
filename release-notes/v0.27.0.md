# v0.27.0

**Source compatibility:** private fields added to `sandbox.ProofError` mean
unkeyed literals of it no longer compile outside the package. Use keyed
literals such as `&sandbox.ProofError{Code: code, Step: step}`. Nothing else
in this release needs a consumer change.

- Adds `harness.Antigravity` (`"antigravity"`), a CLI engine for Google's
  Antigravity CLI, installed as `agy`, checked against agy 1.4.2. Model
  discovery, account inspection (login, per-model-group quota windows and
  credits), native runs and stream-json sessions are offered.
  - Native runs pass a schema with `--json-schema`, and `Config.Antigravity`
    takes `PermissionMode` (`accept-edits`, `auto` or `plan`) and `Agent`.
  - Sessions take `Policy.AntigravityPermission`. The default,
    `request-review`, is agy's own default, which auto-denies any tool that
    needs approval in a non-interactive run. Every session checks the mode agy
    reports at startup before the first prompt, refuses a substituted model,
    and reports a missing conversation on Resume.
  - A run or turn's usage is the sum of its own responses. agy's result usage
    covers the whole conversation, so a resumed run does not count earlier
    runs again.
  - Constrained completion, restricted or sandboxed sessions, interrupt and
    steer, instructions and provided skills are unsupported with reasons.
    agy reads its login from `~/.gemini`, which no variable relocates, so
    another `Provider.CLI.Home` is refused.
  - A logged-out account inspection reports `logged_in: false` at agy's login
    prompt rather than waiting out its minute-long browser login. A login
    without credits still reports its quota.
- Standalone command sandboxes accept a caller-selected `Timeout` up to
  `sandbox.MaxStandaloneTimeout` (two hours). Sessions and hosted runners keep
  `sandbox.MaxSessionTimeout` (ten minutes); the two-minute default and Start
  without a timeout are unchanged. Proofs and capability claims are unchanged.
- Command sandbox cleanup now reclaims nested read-only scratch directories
  before removal, using anchored no-follow directory handles. File modes and
  outside symlink targets are untouched; cleanup failures still report, and
  stale entries are retried independently. This fixes the 2026-10-05 incident
  in which 271 read-only checkout directories survived every sweep and stalled
  the crew across restarts for about seven hours. macOS also reclaims nonempty
  0000 directories using an anchored, directory-only NOFOLLOW_ANY bootstrap
  before handle verification. Unsupported kernels keep the existing cleanup
  failure instead of following links.
- Selected loopback port requests return as an API (`harness.LoopbackPorts`,
  `LoopbackPorts` and `LoopbackControl` options) that no platform offers yet:
  macOS refuses them by name because Seatbelt cannot confine binds to
  loopback, and Linux and Windows return `not_offered`. See
  [selected loopback ports](selected-loopback-ports.md).
- macOS Loopback wording is corrected: binds and inbound connections are
  allowed on every local interface. `LoopbackLocalOnly` requests the stricter
  contract, refused on macOS and offered for standalone Linux command
  sandboxes. Claude Linux sessions prove per-command Loopback and check for
  socat before launch. See [loopback networking](loopback-networking.md),
  whose Codex section already shipped in v0.26.0's code.
- Sessions finish routing every engine-specific step (launch arguments,
  restricted and sandboxed launches, foreign-policy refusal and login
  inspection) through the engine registry. Behaviour is unchanged.

## Opt-in command process inspection

Adds harness.ProcessInspection, sandbox.Options.ProcessInspection and
session.Commands.ProcessInspection. Linux requests prove the command's own tree
within each Run/Start's existing PID namespace and private /proc. Support is
Unknown until per-Open proof. macOS, Windows and native engines/runs refuse it
with explicit reasons; no broad process-info grant is added.

The inspection-only proof identity is
bwrap-workbench-v5-process-inspection-v3. Non-inspection profiles, mounts, keys
and hosted references are unchanged. Requests alter hosted reference powers.
Failures preserve the process_inspection proof step and never silently fall back.
See the [support matrix and caller example](../README.md#command-process-inspection)
and [pending platform evidence](../design-docs/2026-10-05-process-inspection.md).
External enforcement results are not claimed.

Corrects false Linux refusals from control text in shell argv and ptrace-gated
PID 1 namespace links. Tests log bounded marker-redacted diagnostics; inspection
breaches have specific public wording. Research-only macOS execution grants are
corrected; received 5f70c8c failures and inconclusive results are recorded.
Corrected platform enforcement evidence remains pending.

Research expected markers now arrive through an inherited fixture descriptor,
avoiding observer argv contamination. Observed leaks take precedence over
cancellation. Documentation locates inspection with command APIs and explains
rooted proc-view evidence; public refusal reasons contain no transient revision.
